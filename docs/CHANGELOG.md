## [Unreleased]

### Added

- Phase 13, part 2: Explorer menu, portable mode, installer wiring, i18n and accessibility checks, speed budgets. Settings, Explorer menu adds a Quirewise submenu (up to five tools you choose) and "Open with Quirewise" to the right-click menu of PDF files for the current user only, and removes it again; a second start hands its files to the open window (single instance), and `quirewise.exe --tool <id> -- files` is the command line of an entry. The installer now carries the worker and the PDF engines (`scripts/package/stage-installer.ps1`, `tauri.bundle.conf.json`), removes the Explorer menu when uninstalled, and `scripts/package/make-portable.ps1` builds the portable zip. Layouts use logical CSS properties (a lint rule keeps it so) and numbers follow the language. Axe runs on the Recipes screen too, and `crates/worker/tests/perf.rs` measures the merge and first-thumbnail budgets. Adds `domain::explorer`, `infrastructure::explorer` (reg.exe writer), ADR-0012 and `docs/guides/installation.md`.
- Phase 13, part 1: Recipes (Appendix A row 58). Chain tools into a recipe, save it, rename it, export and import it as a JSON file, and run it on chosen files or a whole folder (sub-folders optional, links never followed). Each file runs through every step in order, one status line per file names the failing step, retry failed and cancel work as for one tool. Adds `domain::recipe` (chain rules and the export format), `application::recipe` (the list and the chained run through the normal unit runner), recipe support in the batch queue, `qw recipe`, a Recipes screen with one option form per step and the recipes in the command palette, `docs/tools/recipes.md` and ADR-0011.
- Phase 12: local AI (Appendix A rows 12, 56 and 57, and the AI parts of rows 29 and 54). Smart Split proposes where parts start from an instruction in your own words, shows them, and makes exactly what you checked. AI Summarizer writes a short, medium or long summary in about 36 languages as a PDF or Markdown. Translate PDF translates each block of text and writes it where the text was (the old text is removed from the page), or as flowing text. Redact can add the personal details the model finds to its words, and PDF to Markdown can tidy its prose. The model runs on this computer: the llama.cpp server (MIT) as an on-demand component with model files whose license is shown before they download, or an Ollama server on the loopback address after consent. Off by default. Adds the `ai-llamacpp` engine (OpenAI-compatible chat over loopback, streamed and cancellable, server started outside the worker caps in a job of its own), Unicode text in PDFs with installed fonts (composite fonts with a map back to characters), a text-document writer, `scripts/fetch/fetch-llama.ps1`, ADR-0010 and the docs `docs/tools/smart-split.md`, `ai-summarizer.md` and `translate-pdf.md`.
- Phase 11: PDF to PDF/A, Validate PDF/A and the accessibility check (Appendix A rows 30, 31 and 70). PDF to PDF/A normalizes a document (fonts embedded from the installed fonts, a generated sRGB profile, an XMP packet that agrees with the document information, forbidden actions, scripts, attachments and annotation settings removed), checks it with veraPDF and saves it only when it conforms, trying the next weaker level, an installed Ghostscript (opt-in `agpl-ghostscript` feature, separate process) and, if the person allows it, pictures of the pages. Validate PDF/A and the PDF/UA check write the broken rules as a web page or as JSON. Adds the `pdfa-verapdf` engine (veraPDF as a separate Java process, an on-demand component), the PDF/A normalizer in `lopdf-ops`, `scripts/fetch/fetch-verapdf.ps1`, ADR-0009 and the docs `docs/tools/pdf-to-pdfa.md`, `validate-pdfa.md` and `check-pdfua.md`.
- Phase 10, part 3: Digital signature and Verify signatures (Appendix A rows 61 and 62): PAdES signatures (CMS, `ETSI.CAdES.detached`) appended as a new revision, with a PFX or P12 file or a certificate of the Windows store (the key stays in Windows through CNG, so smart cards and tokens work), visible or invisible, reason, place and contact, filling an existing signature field, certifying with DocMDP, and the levels B-B, B-T (time stamp), B-LT (revocation answers stored in the file) and B-LTA (time stamp over the whole file) behind explicit consent for the internet. Verify signatures writes a PDF report on the signature, later changes, the certificate chain against the Windows roots and your own file, revocation (stored answers or the servers, with consent) and time stamps. Adds the `sign-cms` engine, the web client in infrastructure (the only other place that uses the network besides component downloads), a certificate chooser in the option form and the docs `docs/tools/digital-sign.md` and `docs/tools/verify-signatures.md`.
- Phase 10, part 2: Compare (Appendix A row 55): compares two PDFs by text (line diff across the whole file, so moved text is not a change) and by look (pixel diff with a tolerance, overlay in red and blue) and writes a PDF report with a summary, the text changes side by side and a picture of each page that differs. Per-tool doc in `docs/tools/compare.md`.
- Phase 10, part 1: Redact (Appendix A row 54): removes text, pictures, lines and shapes, annotations and form values under drawn areas and under every match of words, patterns and kinds of text (e-mail, telephone, IBAN, card number) from the page content itself, draws boxes over them, reads the result back and replaces pages it cannot trust with a picture of the page. Adds the content-stream redaction engine (`lopdf-ops`), a character reader on the PDFium layout reader, a preview of matches in the page editor and `docs/tools/redact.md`.
- Phase 9: Editor and forms (Appendix A rows 42, 43, 45, 46 and 53): Edit PDF (text with standard or installed fonts, pictures, shapes, links, patches, and change of existing text), Annotate (highlight, underline, strike-out, notes and freehand as real annotations with appearance streams), Fill and sign (read and fill AcroForm fields, then signatures, initials, stamps and dates), Sign PDF (drawn, typed or picture signatures, kept for later sealed with Windows DPAPI) and Create forms (text, check box, radio, drop-down and signature fields, with suggestions found from the page that the person confirms). One page editor in the app for all five, with undo, keyboard moves and a details panel. Adds installed-font embedding (`ttf-parser`), the form reader and writer in `lopdf-ops`, the signature store and DPAPI wrapper in infrastructure (the only unsafe code, in one module). Per-tool docs in `docs/tools`.
- Phase 8: Convert from PDF (Appendix A rows 25, 26, 27, 29 and 67): PDF to Word (flowing or exact positions), PDF to PowerPoint (editable text boxes, tables and pictures, or one picture per slide), PDF to Excel (workbook or CSV, tables found by lines or by aligned text), PDF to Markdown and PDF to HTML, all on one pure layout analysis (reading order, paragraphs, headings, lists, tables, running headers removed) with OCR for scanned pages. Adds the PDFium page reader, OCR word boxes and the Open XML writers (`engines/export`). Per-tool docs in `docs/tools`.
- Phase 7: Scans (Appendix A rows 13, 16 and 17): OCR (searchable PDF through an invisible text layer laid over the untouched pages, or a text file; several languages, skip pages with text, deskew first), Deskew (automatic by measuring the tilt, or manual angles) and Scan to PDF (cut away the background, stand photographed pages upright, color, gray or black and white with CCITT G4, optional OCR), with the Tesseract adapter, installed-language list, scanner (Windows dialog) and camera input on the home screen, and the `tesseract` and `tessdata-<code>` components. `scripts/fetch/build-tesseract.ps1` and `scripts/fetch/fetch-tessdata.ps1`. Per-tool docs in `docs/tools`.
- Phase 6: Conversions and the component manager (Appendix A rows 18 to 24, 28 and 68): images to PDF (paper, margins, EXIF turns, HEIC), PDF to images, extract images, PDF to text (plain and layout), TIFF to and from PDF (LZW, Deflate, CCITT G4), Word, PowerPoint and Excel to PDF (Microsoft Office or LibreOffice) and HTML to PDF (headless Edge). The signed component installer (minisign signature, SHA-256, safe unpacking, offline `.qwpkg` packages) with Settings, Components and `qw components`. Inputs gain Word, Slides, Sheet and Html kinds; HTML to PDF can run on a web address with no file. Decimal option fields now have an input (they were not drawn before). Per-tool docs in `docs/tools`, `docs/guides/components.md`.
- Phase 5: Edit tools (Appendix A rows 33 to 41, 49, 50, 65 and 66): page numbers, header and footer, Bates numbering and watermark on a shared stamper (standard fonts, upright on rotated pages); crop, resize, flip, N-up and grayscale; bookmarks (typed or generated from headings), rename by content, attachments and page labels. Option forms gain color, file chooser, line-list and row editors, and the region picker serves any tool that asks for one. Tools that rewrite a password-protected file now keep it protected (qpdf `--copy-encryption`), which resolves open question 30. Per-tool docs in `docs/tools`.
- Phase 4: Optimize and security basics (Appendix A rows 14, 15, 44, 47, 48, 51, 52, 63 and 64): compress (preset, JPEG quality, image resolution, grayscale, strip metadata, object streams), repair (qpdf, then PDFium), remove annotations, flatten (forms and annotations, or every page as a picture), edit metadata, protect (AES-256 or AES-128, permissions), unlock, sanitize and linearize. Secrets are redacted in logs and `qw run --options-file` keeps them out of shell history. Option forms gain password fields, grouped permissions, multi-select kinds, remove switches and fields that depend on another. Per-tool docs in `docs/tools`.
- Phase 3: Organize tools (Appendix A rows 1 to 11, 32 and 69): merge (PDFs and images), alternate and mix, organize, split by ranges, every N pages, bookmarks, in half, size and text, extract, remove, rotate and insert blank or duplicate pages. Shared page-copy writer with decrypt, per-page rotation and generated blank pages; outline, crop and scale edits; text in a region; `qw run <tool>` for every tool; output folders are created when missing. Per-tool docs in `docs/tools`.
- Phase 2: PDFium, qpdf and lopdf engine adapters (open, render, text, facts, checks, page copy, structure), persistent worker session for queries, Inspect and Properties, recent files, typed IPC generated from Rust JSON Schema, and the app shell with real page thumbnails, window-wide drop, command palette, batch queue and progress, inline password prompt, keyboard shortcuts and settings. Native binaries are fetched with pinned SHA-256.
- Phase 1: domain rules (units, page range grammar, naming tokens and sanitizing, path policy, error catalog, settings, safety limits, component manifest), application ports, `Tool` contract and `ToolRegistry`, `RunTool` use case, batch retry semantics, worker IPC protocol, atomic never-overwriting file store, settings with migrations, JSON logging, job queue, worker process with Job Object confinement, supervisor, `qw` CLI and fuzz targets.
- Phase 0: repository scaffold, Cargo workspace, Svelte UI shell, Ink and Paper design tokens, visual lint, CI workflows, ADR-0001 to ADR-0005 and the threat model draft.

### Fixed

- Answers of the worker that hold a list (installed OCR languages, fonts, form fields, suggestions, text blocks, redact matches) could not be encoded for the pipe between the app and the worker, because the tag of `QueryResult` sat next to a list. The worker dropped the reply and the app waited for ever. The tag now sits beside the value, the worker sends a failure when an answer cannot be written, and `regression_list_answers_survive_the_wire` covers every list answer.
